# 리스트(List) 자료구조

## 1. 리스트의 정의
- 데이터를 순서대로 나열한 선형 자료구조임.
- 집합과 달리 원소 간의 순서가 유지됨.
- 동일한 데이터의 중복 저장을 허용함.

## 2. 작동 방법
리스트는 크게 두 가지 방식으로 구현됨:
- **순차 리스트 (Array List):** 배열을 이용하여 물리적으로 연속된 메모리 공간에 데이터를 저장함.
- **연결 리스트 (Linked List):** 노드들이 포인터를 통해 논리적으로 연결되어 메모리 상에 흩어져 저장됨.

주요 연산: 데이터 삽입(Insert), 삭제(Delete), 탐색(Search), 참조(Get) 등.

## 3. 인덱스(Index) 개념
- 리스트 내에서 데이터의 위치를 나타내는 번호임.
- 일반적으로 0부터 시작함(Zero-based indexing).
- 인덱스를 통해 특정 위치의 데이터에 직접 접근(Random Access) 가능함.

## 4. 구현 파일 해설

### 4.1. 순차 리스트 (ArrayList.c, .h)
- **구조체 정의:** 배열과 현재 저장된 데이터의 개수(`size`) 포함.
- **장점:** 인덱스를 통한 조회 속도가 매우 빠름 ($O(1)$).
- **단점:** 데이터 삽입 및 삭제 시 요소 이동이 필요하여 속도가 느림 ($O(n)$). 배열 크기가 고정되어 있어 확장이 어려움.

### 4.2. 연결 리스트 (LinkedList.c, .h)
- **구조체 정의:** 데이터 필드와 다음 노드의 주소를 가리키는 포인터 필드(`next`)를 가진 노드(Node) 구조 사용.
- **장점:** 삽입과 삭제 시 포인터만 변경하므로 효율적임. 메모리 공간을 동적으로 할당하여 크기 제한이 없음.
- **단점:** 특정 인덱스 데이터 탐색 시 첫 노드부터 순차 탐색해야 하므로 조회 속도가 느림 ($O(n)$). 포인터 저장을 위한 추가 메모리 필요.

### 4.3. 이중 연결 리스트 (DoubleLinkedList.c, .h)
- **구조체 정의:** 데이터 필드, 다음 노드(`next`), 이전 노드(`prev`) 포인터 필드를 가진 노드 구조 사용.
- **장점:** 양방향 탐색 가능으로 특정 노드에 빠른 접근 가능. 삽입과 삭제가 더욱 유연함.
- **단점:** 단일 연결 리스트보다 더 많은 메모리를 사용함. 구현이 상대적으로 복잡함.

### 4.4 이중 연결 리스트를 활용한 WaitingListSimulation.c
- **목적:** 이중 연결 리스트를 활용한 고객 대기열 시뮬레이션 및 관리.
- **구현메소드:**
   - `reserve()`: 대기열 맨 뒤에 새로운 고객 정보 추가 및 대기 ID 발급.
    - `find()`: 특정 ID 고객 탐색 및 앞선 대기 팀/인원 수 출력.
    - `delay()`: 특정 ID 고객 순서를 대기열 맨 뒤로 미룸.
    - `cancel()`: 특정 ID 고객 대기 예약 취소 및 목록에서 제거.
    - `print()`: 현재 대기열에 있는 전체 고객 정보 출력.
    - `service()`: 대기열 맨 앞(인덱스 0) 고객 서비스 완료 처리 및 목록에서 제거.
    - `modify()`: 특정 ID 고객의 연락처 등 세부 정보 수정.
    - `get_size()`: 현재 리스트의 노드 개수(전체 대기열 크기) 반환.

## 5. 요약 및 비교

## 5. 요약 및 비교
| 특징 | 순차 리스트 (Array List) | 연결 리스트 (Linked List) |
| :--- | :--- | :--- |
| **접근 속도** | 매우 빠름 ($O(1)$) | 느림 ($O(n)$) |
| **삽입/삭제** | 느림 ($O(n)$) | 빠름 ($O(1)$ - 위치를 알 때) |
| **메모리 활용** | 정적 (연속적) | 동적 (불연속적) |
