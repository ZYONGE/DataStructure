# Stack

## 1. 하드웨어와 메모리 구조

- 프로그램은 메모리에 올라가야 실행된다. 이것이 기본적인 폰 노이만 구조이다.
- 폰 노이만 구조는 명령어와 데이터를 같은 메모리 공간에 저장한다.
- 하버드 구조는 명령어 메모리와 데이터 메모리를 분리한다.
- 실제 현대 컴퓨터는 완전한 한쪽 구조만 쓰기보다, 폰 노이만 구조를 기반으로 하되 캐시나 내부 구조에서 하버드식 분리를 일부 활용하는 경우가 많다.

정리하면 다음과 같다.

- 폰 노이만 구조: 프로그램과 데이터를 같은 메모리 공간에서 관리
- 하버드 구조: 프로그램과 데이터를 분리된 메모리 공간에서 관리
- 현대 시스템: 주기억장치는 통합해 두고, CPU 내부 캐시나 명령어/데이터 경로는 분리해 성능을 높이는 방식이 많다.

## 2. 캐시 메모리

- CPU는 매우 빠르지만 DRAM(주기억장치)은 상대적으로 느리다.
- 이 속도 차이를 줄이기 위해 CPU 내부 또는 매우 가까운 위치에 캐시 메모리를 둔다.
- 캐시는 자주 사용하는 데이터나 명령어를 임시로 저장해 평균 접근 시간을 줄인다.

캐시가 빠른 이유는 다음과 같다.

- CPU와 물리적으로 가깝다.
- DRAM보다 빠른 SRAM으로 만들어진다.
- 최근 사용한 데이터 또는 인접한 데이터를 다시 사용할 가능성이 높다는 지역성(locality)을 활용한다.

지역성은 크게 두 가지로 본다.

- 시간 지역성: 방금 사용한 데이터를 곧 다시 사용할 가능성이 높다.
- 공간 지역성: 어떤 데이터를 사용했다면 그 근처 주소의 데이터도 곧 사용할 가능성이 높다.

따라서 배열처럼 연속된 메모리를 순차적으로 접근하면 공간 지역성이 좋아 캐시 효율이 높아질 수 있다.

## 3. SRAM과 DRAM

- 캐시는 주로 SRAM(Static RAM)을 사용한다.
- 메인 메모리는 주로 DRAM(Dynamic RAM)을 사용한다.

차이는 다음과 같다.

- SRAM: 빠르지만 비싸고 집적도가 낮아 크게 만들기 어렵다.
- DRAM: 상대적으로 느리지만 저렴하고 대용량 구성이 쉽다.

즉, 캐시는 작고 빠르게, 주기억장치는 크고 비교적 느리게 설계된다.

## 4. 연산 장치 용어 정리

- CPU (Central Processing Unit): 범용 연산을 담당하는 기본 처리 장치
- GPU (Graphics Processing Unit): 원래 그래픽 처리용이지만, 현재는 대규모 병렬 연산에도 널리 사용됨
- NPU (Neural Processing Unit): 인공지능 추론, 행렬 연산 등 신경망 계산에 특화된 처리 장치
- LPU: 문맥에 따라 의미가 달라지는 용어이며 CPU, GPU, NPU, TPU처럼 보편적으로 표준화된 명칭은 아님
- TPU (Tensor Processing Unit): 텐서 연산과 딥러닝 처리를 위해 설계된 특수 목적 프로세서

## 7.Stack의 추상 자료형

- init(): 스택을 초기화한다. `top`을 초기 상태(예: -1)로 설정하고, 비어 있는 스택으로 만든다.
- push(e): 원소 `e`를 스택의 top 위치에 삽입한다. 스택이 가득 찬 경우(overflow) 삽입할 수 없다.
- pop(): 스택의 top 원소를 제거하고 그 값을 반환한다. 스택이 비어 있으면(underflow) 제거할 원소가 없다.
- is_empty(): 스택이 비어 있으면 참(true), 아니면 거짓(false)을 반환한다.
- is_full(): 스택이 가득 차 있으면 참(true), 아니면 거짓(false)을 반환한다. (배열 기반 스택에서 사용)
- peek(): top 원소를 제거하지 않고 값만 반환한다. 스택이 비어 있으면 조회할 수 없다.

## 10. 오늘의 학습 정리 (Chap_0403 코드 분석)

### 1) 배열 기반 스택의 기본 연산 이해

- `array_stack.h`는 배열 기반 스택의 핵심 연산을 모두 포함한다.
- `top = -1`에서 시작해, `push()`는 `++top`, `pop()`은 `top--` 형태로 동작한다.
- `is_empty()`, `is_full()`로 경계 상태를 먼저 검사한 뒤 연산한다.
- 스택 연산의 시간복잡도는 `push/pop/peek/is_empty/is_full` 모두 O(1)이다.

핵심 포인트

- 오버플로우(가득 참)와 언더플로우(비어 있음) 처리가 필수
- 배열 기반 스택은 구현이 단순하고 빠르지만, 고정 크기 제한이 있다.

### 2) 스택의 LIFO 특성 검증

- `array_stack.c`는 `1 2 3 4 5 6 7`을 넣고 꺼내면서 `7 6 5 4 3 2 1`이 되는 것을 보여준다.
- 이를 통해 스택의 후입선출(LIFO) 성질을 직접 확인할 수 있다.

### 3) 괄호 검사 알고리즘

- `check_matching.c`는 문자열을 왼쪽부터 순회하며 여는 괄호는 push, 닫는 괄호는 pop으로 짝을 확인한다.
- 오류를 세 가지로 분류한다.
	1. 남는 여는 괄호 (Unmatched left parenthesis)
	2. 남는 닫는 괄호 (Unmatched right parenthesis)
	3. 괄호 종류 불일치 (Mismatched parenthesis)

핵심 포인트

- 스택은 중첩 구조(괄호, 블록, 함수 호출)를 검증할 때 매우 적합하다.
- 문자열 순회 종료 후 스택이 비어 있어야 완전한 정상식이다.

### 4) 중위 표기식 -> 후위 표기식 변환의 원리

- `infix2post.c`는 연산자 우선순위(precedence)와 스택을 이용해 변환을 수행한다.
- 숫자는 바로 출력하고, 연산자는 스택 top과 우선순위를 비교해 pop/push를 결정한다.
- 괄호는 우선순위를 강제하기 위한 제어 기호로 사용된다.

핵심 포인트

- 변환 과정에서 "언제 출력하고 언제 보류(스택 저장)하는지"를 구분하는 것이 핵심이다.
- 입력 처리가 끝난 뒤 스택에 남은 연산자를 모두 출력해야 완전한 후위식이 된다.

### 5) 후위 표기식 계산

- `post.c`는 후위식을 한 글자씩 읽는다.
- 피연산자면 push, 연산자면 두 값을 pop해서 계산 후 결과를 push한다.
- 최종적으로 스택에 하나 남는 값이 계산 결과다.

핵심 포인트

- 후위식은 연산자 우선순위를 별도로 처리하지 않아도 된다.
- pop 순서가 중요하다. 보통 `b op a` 형태가 되도록 순서를 맞춰야 한다.

### 6) 오늘 코드에서 확인한 개선 체크리스트

- `infix2post.c`에서 닫는 괄호 처리 시 pop한 연산자를 출력해야 하는데, 현재는 `c`를 출력하는 코드가 있어 결과가 틀어질 수 있다.
- `infix2post.c`에서 입력 처리 후 스택 잔여 연산자 출력 단계가 빠져 있어 후위식이 완성되지 않을 수 있다.
- `post.c`에서 뺄셈/나눗셈은 pop 순서에 따라 결과가 달라지므로, 계산식 순서를 점검할 필요가 있다.
- `check_matching.c`의 사용자 입력은 현재 공백 없는 입력(`scanf("%s")`) 기준이므로, 공백 포함 식을 받으려면 `fgets()`가 더 적합하다.
